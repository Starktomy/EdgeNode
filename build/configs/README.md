### 构建版本

使用 Go 1.27.4，API、Admin、Node 和同级 `EdgeCommon/` 必须使用本次配套版本。Node 仍需 `CGO_ENABLED=1` 和 C 编译器；交叉构建 Linux ARM64 时使用 `CC=aarch64-linux-gnu-gcc`。CI 拉取的 Common 也必须包含新的 RPC 和健康检查签名包。

Pebble 保持 v1 的存储格式，升级至 v1.1.5；SQLite 升至 v1.14.53。已用临时数据库验证旧版本写入、新版本读取和回写、旧版本再次读取，未主动提高 Pebble 格式版本。gopsutil 保留 v3 的导入路径，跨主版本迁移需要另行验证。

### 可信前置代理

默认仅使用 TCP 连接的来源 IP。启用管理端的“经过代理”或自定义客户端 IP 请求头时，必须在节点服务环境中设置 `EDGE_TRUSTED_PROXY_CIDRS`，例如 `10.0.0.0/24,2001:db8:1::/64`，列出实际前置代理的来源网段；重启进程后生效。空配置或非法 CIDR 会禁用转发头解析。

仅可信来源可以提供 `X-Forwarded-For`、`X-Real-IP` 或已配置的自定义头。XFF 从右向左剥离可信代理；前置代理必须覆盖自定义头，并按协议追加实际来源地址。代理声明的客户端不继承节点内部 IP 或回环地址的自动白名单。

升级前先为所有使用代理模式的节点配置这些网段，再滚动更新；在少量节点核对访问日志中的真实客户端 IP 和 WAF 命中情况。不要将 `0.0.0.0/0` 或 `::/0` 作为可信代理网段。

### 安全检查兼容性

请求和响应体检查均有硬预算；请求采用 WAF 的 `maxRequestBodySize`，同时受 8 MiB 进程护栏限制，响应体检查上限为 8 MiB，每次检查的读体时限为 15 秒。检查内容超过字节预算会分别返回 413 或 502，超时或解析/编码错误会拒绝请求，不再按已通过的部分内容放行。仅启用需要检查 Body 的规则才会缓冲，未检查 Body 的合法大上传仍按网站的上传上限流式传输。

本地静态文件通过受根目录约束的文件句柄读取：父目录、根目录外符号链接、编码后隐藏路径会被拒绝，站内相对符号链接和首页通配符仍可使用。显式 URL 过滤同时检查解码后的目标路径。

API 健康检查现在要求以节点密钥签名、有效期 60 秒并绑定目标请求的探测头，旧 Base64 探测头按普通请求处理。滚动升级期间先暂停健康检查的自动下线/自动 DNS 摘除，升级支持签名的 API，再升级一个边缘节点并核对探测状态，然后继续更新其余节点，最后恢复自动动作；不同节点之间不可复用探测头。

### 源站、认证服务与缓存

HTTPS/TLS 源站默认验证证书链及主机名，要求 TLS 1.2 以上。私有 CA 使用节点环境变量 `EDGE_ORIGIN_CA_FILE`，或源站关联的 CA 证书；双向 TLS 的客户端证书仍可使用。`EDGE_ALLOW_INSECURE_ORIGIN_TLS=true` 仅用于显式的临时迁移，完成证书配置后应移除。外部 URL 认证服务同样验证证书，私有 CA 使用 `EDGE_AUTH_CA_FILE`；认证子请求不得通过重定向或变量展开切换到其他来源。启用却无效的认证策略会拒绝访问。

API 到节点的 HTTPS 健康检查使用 `EDGE_HEALTHCHECK_CA_FILE`（设置在 API 服务环境）；探测不跟随重定向。RPC 使用独立的 `EDGE_RPC_CA_FILE`。显式配置的 CA 文件缺失或无效时会报错，不能回退到跳过验证。

缓存默认排除 `private`、`no-store`、`no-cache` 响应，以及未由源站显式允许共享的 Authorization、Cookie、Set-Cookie 响应。`Vary` 不匹配会回源；同一基础 key 当前保存一份表示，未实现所有变体并存。冷缓存合并只适用于无请求体、无授权或 Cookie 的 GET；等待者最多等待两秒，可取消，之后按正常路径回源。它限制合并登记数量，不是全部源站连接的并发限额。

流量统计的服务总量与可采样的域名细分分开：每服务最多暂存 256 个域名细分桶，继续输出原有前 20 项报表；被省略样本由 `DroppedDomainSamples()` 计数，不扣减服务总量。统计落盘及至少一次日志的边界见 `internal/delivery/README.md`。
